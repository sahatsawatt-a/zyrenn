# Code map

Where each part of Zyrenn lives. The parts and their codes (CMP-n, CAP-n) are
the product tree kept in the app itself: project **ZyrenN**, Product page (or
`get-product` over MCP). Read the tree for what a part does and what a change
to it reaches; read this for where its code is.

Each feature keeps the same shape front and back:

| Layer                      | Where                                                                    |
| -------------------------- | ------------------------------------------------------------------------ |
| Routes                     | `routes/features/{feature}.php`, required from `routes/web.php`          |
| Controllers                | `app/Http/Controllers/{Feature}/`                                        |
| Models                     | `app/Models/{Feature}/`                                                  |
| Logic                      | `app/Support/{Feature}/`                                                 |
| MCP tools                  | `app/Mcp/Tools/{Feature}/`, base class `app/Mcp/Tools/{Feature}Tool.php` |
| Pages (Inertia)            | `resources/js/pages/{feature}/`                                          |
| Components and composables | `resources/js/features/{feature}/`                                       |
| PHP tests                  | `tests/Feature/{Feature}*Test.php`, `tests/Unit/`                        |
| Browser suites             | `tests/e2e/{feature}*.mjs` (rules: `tests/README.md`)                    |

### Boards, inside

`resources/js/features/boards/`:

| Folder       | What is in it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model/`     | What an item is: items, geometry, layers, rows, shapes, styles, templates, connectors (`routing.ts` routes a board's lines together: round items, in lanes, labels clear), guides                                                                                                                                                                                                                                                                                                                                                               |
| `drawing/`   | How items are painted wherever a board is drawn (editor, render, note embeds): BoardView and BoardNode; BoardItem, which picks how each item is drawn; `kinds/` with a component for each bigger kind (frame, picture, video, symbol, library shape, connector, label); `itemLook.ts` for colours, edges and effects; labels, paint, blur, pictures, videos, theme; `sketch.ts` + `kinds/SketchShape.vue` for lines drawn by hand (Rough.js, seeded by the item's id), `fonts.ts` for the handwritten fonts (self-hosted, Thai hand after each) |
| `canvas/`    | The editor: BoardCanvas and its bar, zoom, others' pointers, layers and shape panels; `use*` for camera, gestures, shortcuts, drawing, sync, panels, placing, the frame menu, resize handles (`useTransformer`) and drawing only what is on screen (`useOnScreen`)                                                                                                                                                                                                                                                                              |
| `inspector/` | The side panel: InspectorPanel picks the sections that apply; each section is its own component (item actions, part, colours, label, picture, geometry, board, look, hand-drawn, connector, structure), with the pickers and icons they use                                                                                                                                                                                                                                                                                                     |
| `deck/`      | Slides: the deck's look, layouts, presenting (`useShow`, `usePresenting`), animations and transitions (`build.ts` the rules, `useBuild` playing them, `SlideAnimations` / `ItemAnimation` / `StepRow` in the panel), the present bar and notes (`PresentControls`), the presenter window                                                                                                                                                                                                                                                        |
| `pen/`       | The vector pen and SVG path data                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `circuit/`   | Circuits: symbols, layout, solving, logic, and `useBoardCircuit` for a circuit live on a board                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `lib/`       | JSON shared with PHP (shapes, styles, icons, templates, deck, animations)                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

## Adding something

- **A workflow step:** its definition in `Support/Workflow/NodeTypes.php` (or
  `ServiceKinds.php` for a service's, `CommonKinds.php` for the everyday ones:
  feeds, CSV, dates, numbers, text, hashes, Slack, Discord, email), naming the
  class that runs it in `runs`; the class in `Support/Workflow/Steps`. A step
  that gives out only what is new remembers what it gave in `Support/Workflow/Seen.php`.
  A step's icon and colour for its group: `features/workflow/steps.ts`.
- **An MCP tool:** the class in `Mcp/Tools/{Feature}/`, listed once in
  `Mcp/Servers/Toolset.php`, in the folder of the part a key allows it by
  (`Mcp/Scopes.php`: a name starting List/Get/Search only reads); anything clients must know goes in
  `Mcp/Servers/Instructions.php`.
- **Something the headless browser does:** a route in `docker/chrome/server.mjs`,
  asked through `Support/Chrome/Chrome.php`.
- **A call to Telegram or LINE:** through `Support/Connections/{Telegram,Line}.php`.
- **A library for "Run code":** added by an admin on /admin/code (`CodeAdminController`, `Support/Workflow/Code/{CodeLibraries,CodeSettings}`), kept in `code_libraries`; JavaScript ones are bundled by `docker/code/server.mjs` `/install` and loaded behind `require()` in `run.mjs`; Python ones are the Python runner's (`Code/PythonRunner`, `docker/python`).
- **A call to Stripe:** a step in `Support/Workflow/Steps/StripeCall.php` (defined in `ServiceKinds::stripe()`; amounts in the currency's smallest unit, every make under the step's idempotency key); events arrive at `HookController::stripe`, shaped by `Envelope::stripe`.
- **A call to GitHub:** a step in `Support/Workflow/Steps/GithubCall.php` (defined in `ServiceKinds::github()`); what GitHub sends arrives at `HookController::github`, shaped by `Envelope::github`.
